До демонстрации две недели, а у команды как обычно двое пашут а семеро кхмкхм машут: у двух человек по 120–150%, у двух - по 33–40%.

Итого по плану 75 часов при доступных 80, получается часы есть, просто находятся не в том месте не в то время

Что можно передать:



тестировщику - подготовку тест-кейсов, регрессию и приёмку демо



дизайнеру - недостающие макеты и проверку интерфейса на сборке



аналитику - описание контракта API



Что передавать нельзя: правку кода API на тестировщика, проектирование БД на дизайнера



Тут нужна квалификация, а не свободные часы - иначе получим дважды переделанную работу

Решение руководителя

1. Что устраняем в первую очередь - отсутствие договорённости о том, каким должен быть API, и неясный приоритет. Виноватых не ищем: оба правы, потому что контракта не было
2. Что фиксируем - контракт API (адреса, поля, формат ошибок), срок его готовности, правила изменения контракта и приоритет работ: стабилизация БД -> API -> фронт
3. Кто отвечает за API - контракт пишет аналитик, утверждает руководитель проекта, backend реализует. Один ответственный, а не "все и сразу"
4. Что делаем параллельно - фронт собирает интерфейс на mock-данных по контракту, тестировщик готовит кейсы и проверяет уже готовые части, дизайнер закрывает недостающие макеты. Никто не ждёт целиком готовый backend
5. Как контролируем - короткий статус каждый второй день, доска задач с ограничением "в работе не больше двух задач на человека", сборка для тестировщика раз в неделю по пятницам, пересчёт загрузки перед каждой демонстрацией
